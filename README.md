# FK Lab

物理で蹴るフリーキック・ラボです。「ボールのどこを、どの向きに、どの強さで蹴ると、どんな力が働いて、なぜそう曲がる（落ちる・揺れる）のか」を、3D と力ベクトルで見える化します。

ゲームではなくラボです。操作感や演出で市販のサッカーゲームと競うのではなく、物理的な筋の通り方と、曲がる理由が分かることを狙っています。

- コードはすべて Claude Code（モデル: Fable 5.2）が書きました。制作の記録は [docs/LOG.md](docs/LOG.md) にあります。
- 空力係数などの物理パラメータの多くは**仮定値**で、実測で検証したものではありません（[一覧](#仮定値の一覧)）。
- 画像・3D モデル・音声ファイルは使っていません。ボールの模様、ゴール、ネット、ピッチ、選手、スタジアム、効果音は、すべてコードで生成しています。

## デモ

デモ URL と GIF は、公開後にここへ載せます。撮影の手順は [docs/DEMO.md](docs/DEMO.md) にあります。

## 30 秒で試す

1. 「蹴る」を押す。お手本のカーブが、壁を巻いてゴールへ向かう。
2. 判定が出ると「なぜ曲がった？」パネルが開く。どの力が何 m 曲げたかが分かる。
3. 右の円（ボールを後ろから見た図）で、蹴る点をドラッグして変える。左を蹴ると右へ曲がり、下を蹴ると伸び、中心を蹴ると無回転で揺れる。

## できること

| 機能 | 内容 |
|---|---|
| フリーキック | ボールの位置、蹴る点、向き、強さを決めて蹴る。予測線が常に出る |
| 力の可視化 | 重力、抗力、マグヌス力、ナックル横力を色分けした矢印で表示。速さ、回転数、Re、C_D、S も出す |

| 比較 | 蹴った軌道を残して、次の軌道と重ねる |

| 伝説の FK | 有名なフリーキック 2 本を、推定パラメータで再現 |
| 守備 | 壁（0〜5 人、ジャンプあり）と、難易度 3 段階の GK |
| 視点 | キッカー、GK、真上、真横、追従 |

PC とスマホ（タッチ操作）の両方で動きます。

## 物理モデル

ボールを 6 自由度の剛体として、固定ステップ（1 ms）の 4 次ルンゲ＝クッタ法で積分します。姿勢はクォータニオンで持つので、ボールの模様が回転して見えます。

```
m·dv/dt = 重力 + 抗力 + マグヌス力 + ナックル横力
```

座標系は右手系で、x がゴール方向、y が上、z がキッカーから見て右です。

### 抗力とドラッグクライシス

```
F_D = ½·ρ·A·C_D(Re)·|v|·v   （v の逆向き）   Re = |v|·2R/ν
```

抗力係数 C_D は一定ではありません。速い球（超臨界域）では約 0.18 と小さく、遅い球（亜臨界域）では約 0.45 と大きくなります。境目はレイノルズ数 約 2.5×10⁵（速さにして約 17 m/s）で、このモデルではシグモイド関数でなめらかにつないでいます。

球が減速してこの境目に近づくと、抗力係数が急に上がります。速度が落ちるほどブレーキが強くなるので、ボールは終盤で「落ちる」ように見えます。HUD の Re と C_D、「なぜ曲がった？」パネルの説明で確かめられます。

### マグヌス力

```
F_M = ½·ρ·A·C_L(S)·|v|²·(ω̂ × v̂)   S = R·|ω|/|v|   C_L = a·S/(b + S)
```

回転軸と進行方向の両方に垂直な向きへ働きます。バックスピンなら上向き、上から見て時計回りなら右向きです。回転軸が進行方向と平行（ジャイロ回転）なら働きません。

### ナックル（無回転）

無回転のボールの揺れは、マグヌス力ではなく、後流の渦が不規則に剥がれることで生じる横向きの力によるものとして扱います。

```
F_K = ½·ρ·A·C_K(t)·|v|²   （速度に垂直な平面の中で、向きが変わる）
```

- C_K(t) は、位相がランダムな 4 本の正弦波の和です。代表周波数は f = St·|v|/(2R)（St はストローハル数）で、その 0.08〜1 倍の成分を重ねています。
- 振幅は、回転が小さいほど大きく、S が 0.1 に達するとゼロになります。超臨界域で大きく、亜臨界域で小さくなります。
- 乱数のシードを固定できます。同じシードなら同じ揺れ方になるので、再生や比較ができます。

これは流れを解いているのではなく、揺れ方をそれらしく表す簡易モデルです。

### キック

```
v₀ = e·J/m          （e: キック効率、J: 力積）
ω₀ = κ·(r × J)/I    （r: 重心から接触点へのベクトル、κ: 足との摩擦による伝達係数）
```

中心を蹴れば r と J が平行なので回転はゼロになり、ナックルになります。外側をこするほど強い回転がかかります。

### 衝突

地面（反発と摩擦によるバウンド、転がり）、ポストとクロスバー（円柱）、壁の選手と GK（円柱）との衝突を扱います。

ゴールネットは、質点とバネの格子として計算しています。網はたるんでいて重みで垂れ、糸は引っぱられたときだけ力を出します。ボールと網は互いに力を及ぼし合うので、飛び込んだボールは網を押し込み、絡め取られて落ちます。

## ゴールキーパーの考え方

GK は次の決まりで動きます。

1. キックの瞬間から、反応時間（0.2〜0.35 秒）が経つまでは動かない。
2. ボールの現在の位置と速度から、**等速直線運動を仮定して**到達点を予測する（予測には誤差を加える）。
3. 予測点へ寄り、到達が近づいたら飛びつく。飛びついたら狙いは変えられない。

予測が等速直線なので、大きく曲がる球や揺れる球ほど GK は外されます。まっすぐな球は読まれやすく、曲がる球は読まれにくい。物理の違いがそのまま勝負に出るようにする、というのがこの設計の意図です。

難易度は、反応時間と予測の誤差の大きさで変えています。体の動き（横移動の速さ、倒れ込む速さ）は共通です。

## 逆算モード

ゴール面上の狙う点をクリックすると、そこを通る蹴り方（左右の狙い、高さ、強さ、こする量）を Nelder-Mead 法で探します。計算は Web Worker で行うので、画面は止まりません。探索の途中で試した軌道を、薄い線で重ねて見せます。

壁に当たる蹴り方には罰則を付けています。同じ点を通る蹴り方がいくつもあるときは、飛んでいる時間が短いもの、GK の最初の読みを外すものを少し優先します。

## 伝説の FK

ロベルト・カルロスの 1997 年のフリーキック（アウトサイドで大きく曲がる球）と、本田圭佑の 2010 年のフリーキック（無回転）を再現するプリセットがあります。

パラメータは**推定値**です。映像や記録から数値を取ったものではなく、それらしい位置と球筋になるように逆算モードで求めました。実在の選手の肖像や公式の素材は使っていません。

## 動かし方

Node.js 24 以上が必要です。

```sh
npm install
npm run dev      # 開発サーバー（/graphs.html に物理コアのグラフ）
npm test         # ユニットテスト（Vitest）
npm run build    # dist に静的サイトを出力
npm run sim      # 物理コアの数値をコンソールに出す
```

確認用のスクリプトが `scripts/` にあります。

| スクリプト | 用途 |
|---|---|
| `node scripts/preset-check.ts` | お手本の蹴り方が、ゴールラインのどこを通るか |
| `node scripts/shot-check.ts` | お手本の蹴り方が、GK の強さごとにどう判定されるか |
| `node scripts/keeper-check.ts` | 狙う位置 × 球種 × 難易度のセーブ率の表 |
| `node scripts/legend-fit.ts` | 伝説の FK のパラメータを逆算で求める |
| `node scripts/params-table.ts` | README の仮定値の一覧を出力する |

## 分かっている制限

- 空力係数は仮定値で、風洞や実測のデータに合わせていません。数値は「傾向を見るためのもの」として扱ってください。
- ナックルは、渦の剥離を正弦波の和で表した簡易モデルです。ボールの縫い目や向きの影響は入っていません。
- キックモデルは、蹴る点がずれても初速が変わりません（実際は、こするほど初速が落ちます）。
- 60 fps は PC の Chrome で確認しました。スマホの実機では確認していません。
